# Fase 3F — Plano de implementação

**Objetivo:** gerar candidatos revisáveis de arquivos ou trechos e exportar
somente decisões humanas a partir dos originais.
**Spec:** `Docs/03_FASE_3_INTELIGENCIA_EDITORIAL_E_ORGANIZACAO_AUTOMATICA.md`, seção 13.
**Arquitetura:** uma tabela para candidatos e decisões; usa ranking 3E e trechos
3C. Exportação assíncrona usa jobs existentes, ffmpeg e pasta local configurada.

- [x] Migrar `select_candidates`. Gerar um candidato por arquivo e pelos trechos
  úteis conhecidos. Sugerir o melhor take por conjunto de thumbnails semelhantes,
  mantendo todos os outros acessíveis. Sem score completo, permitir revisão manual.
  Reprocessamento não sobrescreve decisões humanas. Testar limites e isolamento
  entre viagens.
- [x] Expor API autenticada para gerar/listar candidatos, aceitar inteiro,
  aceitar trecho com IN/OUT válidos ou rejeitar. Auditar alterações. Integrar à
  tela editorial com preview e status. Testar CSRF, revisão e persistência.
- [x] Exportar selects confirmados para uma nova pasta local por job, com FAST
  (`-c copy`) e ACCURATE (H.264/AAC). Validar caminhos e SHA-256 dos originais
  antes de escrever; usar nomes seguros; criar `SELECTS/`, manifesto JSON e CSV.
  Publicar pasta apenas após sucesso, manter erros sanitizados. Testar sem ffmpeg
  real por runner falso; conferir recuperação após reinício.
- [x] Documentar operação, rodar suíte Windows, Ruff e mypy e revisar diff.

**Escolha do usuário:** pasta local no servidor, não ZIP. `DMM_SELECTS_ROOT`
opcional; padrão ao lado do SQLite. Fonte OMV permanece somente leitura.
